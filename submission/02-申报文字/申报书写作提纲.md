# 申报书写作提纲

按官方 Word 模板逐项填报，以 [[产品愿景与参赛制作总计划]] v2 的整体产品设计为主线。报名字段与应用发展阶段按实际材料填写。

**项目概括**　园合 ParkWeave 的整体方案面向企业成长与园区运营，将企业目标、园区服务、空间设备和产业伙伴组织为可协同的服务网络。通过需求理解、机会发现、多方案推演、资源统筹、变化重编排和交付反馈，为企业提供连贯服务，为运营方提供协同机制，为园区提供可复用的产业服务能力。

| 官方章节 | 建议写什么 | 可用证据或待补材料 |
| --- | --- | --- |
| 项目基础信息 | 正式项目名、应用行业及场景、核心技术、应用发展阶段 | 对照实际报名信息和实现证据填写 |
| 背景及意义 | 从企业获取服务、园区组织协作、资源供需匹配三个角度说明行业痛点。 | 访谈、流程记录与有出处的行业资料 |
| 主要场景及功能 | 按六大模块说明完整能力，以企业成长串起入驻、研发、人才、政策与产业协作，深入呈现复合需求及变化。 | 总览、场景图和操作截图逐一对应用户任务 |
| 实现方案 | 解释目标约束、服务网络、模型候选、规则校验、责任协同与交付记忆的配合，以及园区系统接入和部署路径。 | 架构图、服务依赖图、方案对照与业务输出 |
| 项目创新点 | 用变化前后对照解释为何要显式记录目标、约束、责任与版本。用冲突拦截和回执纠正解释人工确认的具体位置。 | 资源冲突图、方案差异、回执版本和历史归档图 |
| 市场分析 | 明确园区运营企业、产业服务平台和多园区集团的需求，分析采购动机、业务适配与推广条件。 | 市场数据注明出处，付费意愿通过调研核实 |
| 商业模式分析 | 说明平台使用、目录配置、系统对接和运维的交付内容，以及单园区到多园区的复制方式。 | 交付清单、配置边界和成本调研 |
| 应用情况（如有） | 集中说明案例操作、输出与评价方法，实际应用记录按可核验材料填写。 | 运行记录、导出样例、交互记录与实测指标 |
| 社会效益 | 从降低中小企业服务门槛、提高共享资源效率、扩大专业服务覆盖和促进产业协作展开。 | 各项价值对应产品机制与评价指标 |
| 附录 | 放产品实图、案例成果摘要、必要的验证说明和视频二维码。 | 从 03 选图，从 04 获取定稿视频二维码 |

## 案例证据口径

- 主案例采用 40 人技术交流活动，展示目标到归档及导出的完整预设操作。另有 20 人培训对照，证据覆盖方案和资源预检。
- 变化案例是独立事项 `PW-20261108-003`。人数 40→20、时段 14:00–16:00→15:00–17:00、预算 3,000→2,000 元。演示方案调整、资源复验、回执纠正和重开后再次归档。
- 可补测指标包括相同任务的操作步骤数、冲突拦截覆盖数、事项归档字段覆盖率。填写时记录样本、起止条件、人工对照及数据来源。暂无实测值的位置留空。
