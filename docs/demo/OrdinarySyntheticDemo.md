# 从空业务库办理的普通合成演示

2026-10-20 已按本说明实际执行三件新事项的原页面处理函数/HTTP/PG闭环、TXT导出、物理冷启动与两园区企业隔离，见[技术演示记录及边界](../F2/OrdinaryLocalUIDeliveryValidation-20261020.md)。这是助手执行的Linux技术演示；本环境真实Chromium启动受阻，用户人工验收和Windows正式AT仍未验。

第4步的两资源HOLD、组合确认和Case关联另有[正常sandbox Chrome的有界CI记录](../F2/OrdinaryResourceBrowserCIContract-20261020.md)：公开job实际成功，覆盖两域资源页及冷读；资料前置仍由原API准备。该资源场景不将整条办理链升级为全浏览器验收，原step JSON待父侧登录浏览器核对。

本入口新建一个独立Linux合成数据库，在同一库内准备两个明确隔离的合成企业/园区。每套各有企业经办人、资料专员、执行者三种身份、自己的资料目录和两项资源；随后使用原页面、普通API与普通worker。无需手改SQL、Grant、目录、pack或journal。它不是生产安装、真实园区接入或正式批准，也不是V4服务选择/模型演示。

需已有非root Linux、Python3.12和本仓库依赖（包括`pgserver==0.1.4`）。从完整源码根目录运行；不要求`.git`存在。新机器需先按`pyproject.toml`准备Python环境和依赖，本启动器不下载或安装依赖。Windows原生、WSL和其他环境未在本片验收，不能用此入口替代Windows正式AT。

## 青禾园虚构人物与可点击引导

用户已明确允许新造演示数据。需要“青禾科创园 / 云杉智造”首办、再次使用和取消引导时，在新库初始化时明确选择本机模拟目录：

```bash
.venv/bin/python -B -m scripts.ordinary_synthetic_demo setup --with-local-catalog
.venv/bin/python -B -m scripts.ordinary_synthetic_demo serve \
  --state-dir /tmp/parkweave-ordinary-demo-实际值 \
  --local-demo-config /tmp/parkweave-ordinary-demo-实际值/local-demo/config.json --port 8765
```

本指定环境的Python路径是`/workspace/parkweave-venv/bin/python`。使用setup实际输出的路径，打开serve输出的`demo_url`（`http://127.0.0.1:8765/demo`，仅该环境本机可访问）。选择同一state目录下的`sessions.json`，点击“打开原办理页面”启动独立同源窗口，再用本页人物按钮切换身份、示例按钮填表；原业务页面保持独立，不使用iframe或放宽防嵌入策略，所有创建、审核、ADOPT、回执与取消均须明确操作。初始化只生成既有格式的模拟目录、journal与绑定配置，业务记录起初为空；不预插成功事件。`serve`只读取并校验这些既有文件，不能补造或修复。

新模式复用精确配对的`LOCAL_DEMO_CURRENT_PREPARATION`和`LOCAL_SYNTHETIC_DEMO`，候选标记`NO_MODEL`。它不会开放正式来源或原生权限；默认不带这些参数的旧入口继续保持原模式。材料复用仅复制本人同用途通用目录，新诉求、审核和确认独立进行；本演示只验证第二事项独立审核确认后、尚未ADOPT或分派时的取消，第一事项的已办回执仍保留；已接单或已提交回执的取消不属于此演示验收范围。模拟目录包从setup起有效7天，serve不续期或修改旧文件，期满拒绝并保留数据；资源占位和接单窗口有各自期限，过期按原界面拒绝。

需要体验本地资源方案的独立批准时，新建实例使用 `setup --with-local-catalog --with-local-resource-approval`，再按上面同一目录的 `serve` 命令启动。这个可选项只在新库安装本地批准存储；旧实例不会自动补装。启动后，原页面“资源”中选择本人3–8条尚有效的占位（同一资源的不同时段可分别占位），填入已明确采用计划且P1已核验的资料事项编号，依次点击“只读预检此Case交付”、提出方案、明确批准、交付。也可先明确撤销，撤销后不得交付；已消费的批准只留历史，不能撤销既成占用。预检与批准沿用原短期有效期，过期需新预检和新决定，不延长期限。

批准由当前经办人通过本地应用产生，显示“本地来源”；不是外部审批、真实预约、资格认定或履约。它绑定这份资料、原ADOPT、精确计划、当前权限、资源和时段，只可被首次同Case交付事务消费一次。原键只读核对、再次提交同键和冷读保留原回执，不重办；重新批准、计划替换仍沿原门拒绝。新增批准链已做普通API、真实独立进程和局部页面函数检查，尚未做该新增链的真实浏览器验收。 首次成功提出本地方案后，该Case的持久账本决定此交付入口必须使用本地批准；即使重启时漏配模式，预检与新交付也保持拒绝。已消费原键和只读恢复仍严格核验原证明；从未进入本地审批的旧Case保留原交付合同。此约束不改写独立资源组合或直接关联入口的原合同。

## 原普通合成模式

初始化与日常启动分开。在源码根目录、已有`.venv`环境中先执行一次：

```bash
.venv/bin/python -B -m scripts.ordinary_synthetic_demo setup
```

命令输出新建的`state_dir`。每次setup都会产生另一套全新私有目录；已有目录不会被修改。后续始终使用输出的同一目录，例如把下例路径替换为刚输出的实际路径：

```bash
.venv/bin/python -B -m scripts.ordinary_synthetic_demo serve \
  --state-dir /tmp/parkweave-ordinary-demo-实际值 --port 8765
```

看到含`url`、API/worker/PostgreSQL PID的就绪JSON后，打开该127.0.0.1地址。端口被占用时改用另一个1024–65535端口；程序不会停止原监听器。启动器只连接本目录的私有Unix socket，不读取外部DSN或继承Native/demo/模型配置。

状态目录0700、文件私有。只在本机打开其中`sessions.json`，按下表选择一个范围内的角色，把对应值复制到原页面会话输入框。就绪JSON的`available_scopes`也列出角色键，不含会话值；`state.json`的`scopes`列出本次固定配置。

| 合成范围 | 企业经办人键 | 资料专员键 | 执行者键 |
| --- | --- | --- | --- |
| 第一企业 / 第一园区（primary） | `enterprise` | `specialist` | `executor` |
| 第二企业 / 第二园区（secondary） | `second_enterprise` | `second_specialist` | `second_executor` |

六个会话各自独立。不要把会话发到聊天、截图、URL或仓库。三种身份各做自己的动作，切换后重新打开同一资料事项；第二企业必须从自己的“开始资料准备”新建，不能填第一企业的资料编号接着办。界面目录、可选专员/执行者和资源按当前身份读取，不能通过改角色或猜ID越界。测试会话无自动过期；停服务、关网页或重开不撤销会话。

先选第一企业的三个角色，从第一份新输入开始；第二企业随后使用自己的三角色重复这些原有步骤：

1. 企业身份点击“查看可选服务与专员”，填写“A设备维护”的全新合成诉求，选择演示专员，点击“开始资料准备”。普通worker创建新的Run/Case，再进入新资料事项。记录资料事项编号。
2. 在“本次诉求与必需目标”分别点击“本地材料准备”“此Case资源关联”“已有授权本人接单”“合成回执核对”“本地记录重验”，保存诉求与必需目标。依次追加“诉求摘要”和“材料目录”两槽的新文本，明确其合成来源。不要勾选另一个合成协作目标来代替这五项目标。
3. 切换专员会话，打开该资料事项，点击“核对本地资料包”；再切回企业，点击“确认本地资料准备”。查看当前规划预览，点击“采用当前受支持方案并建立步骤”。这是原确定性规划的显式采纳，不调用模型。
4. 在此Case持久步骤计划中明确核验P1。到资源区，以企业身份分别查看并占位两种资源，选当前时间至少一小时后的UTC区间、每项1份；120秒内选中两条占位并“确认这两个合成资源”。回到该资料事项，选择刚确认的组合，填写说明并“确认此Case资源关联”，再核验P2。这里走原两资源组合关联；独立的严格方案批准/交付入口仍关闭。
5. 切换专员，查看此事项的内部分派，选择演示执行者并“记录分派”。切换执行者，从自己的分派中“接受本事项”。切回企业核验P3；执行者进入该接单事项回执，填写新的合成回执并提交；企业“核对当前合成回执”，再核验P4。禁止用“生成本地合成接单报告”或隔离预演代替人工回执。
6. 企业在本地记录中填写说明，依次“重新校验当前一轮”“关闭本地记录”，再明确核验P5。读取逐目标结果后，先点击“生成本次核对包”，等核对包全文出现、下载按钮启用，再点击“重新核对并下载 TXT”。本地结果核验和关闭不代表真实资格、外部受理或线下履约；已有资源占用仍保留。

首次分派后的原步骤窗口最多300秒，不会因刷新或重启延长。材料与资源准备完成后再分派，并及时完成接单、回执和核验；超时准确拒绝，历史保留。资源占位也有独立期限，未确认就可能过期。关闭记录不自动释放资源；后续资源须按原授权从原入口独立取消。

在启动终端按Ctrl+C，只停止这次实际创建的API、worker和PostgreSQL子进程，状态、会话、日志与下载保留。用相同`serve --state-dir`重新启动，企业按原编号打开A事项并重新下载核对TXT。随后切换到`second_enterprise`冷会话，先查看第二范围目录，使用第二专员和第二执行者，从“开始资料准备”提交“B员工培训”的全新诉求与两槽材料，选择第二园区的两项资源，重复完整办理。可使用与第一园区相同的未来UTC时段，各有独立容量；第二企业第一次列表应为空。B应有新的Run、Case、资料、材料evidence、计划、分派和回执编号。A的内容、截止和历史保留，不能复制A的材料、Case或专属证明给B。两范围不得互读或互用Run、资料、目标结果、占用、组合、接单和回执；拒绝不自动补权。

serve只校验既有源码内容、集群/库、权限/目录/资源及实际app SQL ACL，不迁移、不seed、不重发创建票据、不修复撤权或会话。源码、会话或权限改变、未知postmaster标记、锁占用或停止不确认时拒绝并保留现场。查看该目录私有`failure.log`和`logs/`定位；不要反复setup掩盖失败，也不要删除未知锁或进程。新建失败的目录同样保留。

此入口不覆盖旧material-only演示的特定一次setup授权或旧库，也不替换`LOCAL_SYNTHETIC_DEMO` profile。Native permit/writer、正式来源、资源批准provider和V4组合均保持原关闭/互斥边界。数据位于`/tmp`，操作系统或平台清理仍可能丢失，不能称永久保存；保留、撤销及清理须另行明确处理。

当前版本的新setup生成state schema `/2` 和两套固定范围；不升级已有`/1`状态、不向旧库补第二套资料。旧状态保留，应使用原受测`5b36291a22aae8dd74346ae9f2b54c148a4b1ef0`源码启动。新版本遇到旧状态或范围绑定缺失/改变，在启动PostgreSQL前拒绝。两套园区/企业配对并不代表所有园区×企业交叉组合、跨园区迁移或正式模板发布已验收。
