# 从空业务库办理的普通合成演示

本入口新建独立Linux合成数据库，准备三种演示身份、资料目录和两项资源；随后使用原页面、普通API与普通worker。无需手改SQL、Grant、目录、pack或journal。它不是生产安装、真实园区接入或正式批准，也不是V4服务选择/模型演示。

需已有非root Linux、Python3.12和本仓库依赖（包括`pgserver==0.1.4`）。从完整源码根目录运行；不要求`.git`存在。新机器需先按`pyproject.toml`准备Python环境和依赖，本启动器不下载或安装依赖。Windows原生、WSL和其他环境未在本片验收，不能用此入口替代Windows正式AT。

初始化与日常启动分开。在源码根目录、已有`.venv`环境中先执行一次：

```bash
.venv/bin/python -B -m scripts.ordinary_synthetic_demo setup
```

命令输出新建的`state_dir`。每次setup都会产生另一套全新私有目录；已有目录不会被修改。后续始终使用输出的同一目录，例如把下例路径替换为刚输出的实际路径：

```bash
.venv/bin/python -B -m scripts.ordinary_synthetic_demo serve \
  --state-dir /tmp/parkweave-ordinary-demo-实际值 --port 8765
```

看到含`url`、API/worker/PostgreSQL PID的就绪JSON后，打开该127.0.0.1地址。端口被占用时改用另一个1024–65535端口；程序不会停止原监听器。启动器只连接本目录的私有Unix socket，不读取外部DSN或继承Native/demo/模型配置。

状态目录0700、文件私有。只在本机打开其中`sessions.json`，将对应值复制到原页面会话输入框：`enterprise`是企业经办人，`specialist`是资料专员，`executor`是步骤执行者。不要把会话发到聊天、截图、URL或仓库。三种身份各做自己的动作，切换后重新打开同一资料事项。测试会话无自动过期；停服务、关网页或重开不撤销会话。

从第一份新输入开始：

1. 企业身份点击“查看可选服务与专员”，填写“A设备维护”的全新合成诉求，选择演示专员，点击“开始资料准备”。普通worker创建新的Run/Case，再进入新资料事项。记录资料事项编号。
2. 在“本次诉求与必需目标”分别点击“本地材料准备”“此Case资源关联”“已有授权本人接单”“合成回执核对”“本地记录重验”，保存诉求与必需目标。依次追加“诉求摘要”和“材料目录”两槽的新文本，明确其合成来源。不要勾选另一个合成协作目标来代替这五项目标。
3. 切换专员会话，打开该资料事项，点击“核对本地资料包”；再切回企业，点击“确认本地资料准备”。查看当前规划预览，点击“采用当前受支持方案并建立步骤”。这是原确定性规划的显式采纳，不调用模型。
4. 在此Case持久步骤计划中明确核验P1。到资源区，以企业身份分别查看并占位两种资源，选当前时间至少一小时后的UTC区间、每项1份；120秒内选中两条占位并“确认这两个合成资源”。回到该资料事项，选择刚确认的组合，填写说明并“确认此Case资源关联”，再核验P2。这里走原两资源组合关联；独立的严格方案批准/交付入口仍关闭。
5. 切换专员，查看此事项的内部分派，选择演示执行者并“记录分派”。切换执行者，从自己的分派中“接受本事项”。切回企业核验P3；执行者进入该接单事项回执，填写新的合成回执并提交；企业“核对当前合成回执”，再核验P4。禁止用“生成本地合成接单报告”或隔离预演代替人工回执。
6. 企业在本地记录中填写说明，依次“重新校验当前一轮”“关闭本地记录”，再明确核验P5，最后“重新核对并下载TXT”。本地结果核验和关闭不代表真实资格、外部受理或线下履约；已有资源占用仍保留。

首次分派后的原步骤窗口最多300秒，不会因刷新或重启延长。材料与资源准备完成后再分派，并及时完成接单、回执和核验；超时准确拒绝，历史保留。资源占位也有独立期限，未确认就可能过期。关闭记录不自动释放资源；后续资源须按原授权从原入口独立取消。

在启动终端按Ctrl+C，只停止这次实际创建的API、worker和PostgreSQL子进程，状态、会话、日志与下载保留。用相同`serve --state-dir`重新启动，企业按原编号打开A事项并重新下载核对TXT。随后从“开始资料准备”提交“B员工培训”的不同诉求与两槽材料，另选可用区间，重复完整办理；B应有新的Run、Case、资料、计划和分派编号。A的内容、截止和历史保留，不能复制A的Case专属证明给B。

serve只校验既有源码内容、集群/库、权限/目录/资源及实际app SQL ACL，不迁移、不seed、不重发创建票据、不修复撤权或会话。源码、会话或权限改变、未知postmaster标记、锁占用或停止不确认时拒绝并保留现场。查看该目录私有`failure.log`和`logs/`定位；不要反复setup掩盖失败，也不要删除未知锁或进程。新建失败的目录同样保留。

此入口不覆盖旧material-only演示的特定一次setup授权或旧库，也不替换`LOCAL_SYNTHETIC_DEMO` profile。Native permit/writer、正式来源、资源批准provider和V4组合均保持原关闭/互斥边界。数据位于`/tmp`，操作系统或平台清理仍可能丢失，不能称永久保存；保留、撤销及清理须另行明确处理。
