# ParkWeave 四场景工作台重构与验收

本轮以用户粘贴的系统重构要求及明确确认的四张截图为基准。该要求优先于前轮的粗边框、全页楷体、玻璃卡片等视觉尝试。本轮交付从 `codex/frontend-docx-polish-20261104` 开发分支整理，具体提交与合入状态以 Git 历史为准。

## 从代码确认的问题

1. 前轮视觉规则多次追加在两个 HTML 中，字体、边框和尺寸互相覆盖，主工作区的左边线也不统一。
2. 服务输入、三个导航入口和辅助工具使用近似卡片强度，真正的目录读取动作没有明显优先级。
3. 资源目录与长来源说明在表单之前；右栏以“已选组合”为大标题，却先展示表单草稿。预检后的来源、版本、限制又拼成一整段。
4. 协同页按功能堆叠说明和读取按钮；打开详情时继续把整个协同工作区挤进左栏。
5. 资料事项、Case、Run 是不同对象。它们的标识需要保留，但不应在每条列表默认展开。材料准备状态与当前读取是否有效也必须分别显示。

## 实施结果

### 共用规范与交付结构

- `src/parkweave/workspace_design.css`：统一视觉系统。现代系统中文无衬线字体；主标题 26px、模块标题 18px、正文与主要控制 15–16px、次级元数据 13–14px。普通按钮约 40px，输入 42px，触摸模式保留 44px。采用 4/8px 间距、20/24px 主区内边距及低对比细边框。
- `src/parkweave/workspace_design.js`：独立的展示层，组织资源操作、协同分类和详情主从结构。所有业务读取、写入、状态判断仍调用原处理器。
- 两个 HTML 移除前轮追加的视觉覆盖，链接同一份共享 CSS。完整工作台额外加载展示模块；精简资料客户端同步基础控件与字体。
- API 和只读预览入口提供这两个同源静态资源，Python 包清单包含它们。没有引入组件库、字体 CDN，也没有放宽 CSP。

### 服务工作空间

目标输入和“查看可选服务与专员”构成唯一主要任务。按钮仍只读取目录，没有改写成提交申请或开始办理。

继续已有资料事项放在次级区域，字段明确为“资料事项编号”。原三个路径实际是定位现有控件的导航，因此改为文字导航，不制造步骤进度。低频入口保留于“其他入口与记录”，不再做成同等醒目的卡片按钮。

### 资源工作空间

主区按目录读取、资源选择、可见约束、UTC 时段与数量、预检、短期占位组织。容量、开放时间、前后缓冲就近展示；完整名称和原始来源放入可通过键盘打开的资源详情，返回后焦点回到资源选择框。

预检按钮与占位设置分开，但所有输入和提交按钮仍属于原 `resource-form`，原生必填校验与原提交处理器保留。只有原占位按钮真的启用时，视觉上的下一主操作才切换到创建占位。

右栏明确分成“正在填写（尚未选入）”和“已选组合”。预检反馈突出当前结论、容量和“尚未占位”，完整观察时间、来源、版本和本地适用范围保留在“预检依据与范围”。修改输入后按原逻辑失效，并清除旧依据的当前展示。

### 协同工作空间

保留“需要我处理／与我相关”的原入口语义，不冒充新的全量查询或服务器筛选。搜索、阶段条件与清除合为工具栏；计数明确为已加载分类合计与筛选匹配数。

资料事项、派单、执行回执、通知、办理进度和运行核对分别呈现。切换分类只改变展示，不自动读取所有分类。各原读取按钮保持原作用范围，统一放在分类工具栏。

未读取、读取中、已读空结果、筛选无匹配和失败分别呈现。资料事项列表将已有名称和状态分开显示，原始编号可在详情中读取；没有新增更新时间、责任人或待办总数等无依据字段。

### 事项详情

左侧是来自原列表按钮的精简事项导航，点击仍委托原按钮处理器执行；右侧是独立详情滚动区。完整协同页面在详情模式下不再显示。宽度小于 1200px 时使用独立详情视图，保留返回原工作区的入口。

详情以实际事项名称和读取时状态、版本为头部。“概览／材料／记录”各有清楚范围。当前读取失效的警告与原刷新按钮相邻，完全相同的重复报错不再显示多次；原消息没有被改写成资料已更新或业务成功。

材料使用轻量列表，保留名称、版本、原文分行、来源和操作。完整来源元数据仍在原阅读面板中，不做多层套框。资料事项编号、Case 和 Run 编号可按需查看；隐藏或清空原事项时，新展示的编号副本也会清空。

## 术语与业务边界

| 表达 | 对应现有对象／含义 |
| --- | --- |
| 本次目标 | 用户输入的目标文字，不等于已创建事项 |
| 资料事项／资料事项编号 | `preparation` 及其 ID；不是 Case 或 Run 编号 |
| 所属事项 Case | 资料记录绑定的业务事项 |
| 技术运行 Run | 对应技术运行，不等于业务办结 |
| 目录容量、开放时间、缓冲 | 已读目录约束，不代表当前剩余可用性 |
| 正在填写 | 当前表单草稿，不计入已选占位组合 |
| 已选组合 | 原 `combinationSelection` 中的占位记录，不等于已确认预约 |
| 预检通过 | 可尝试短期占位；仍未占位、未预约、外部可用性未知 |

环境标签沿用原服务端页面装配，保留合成工程与本地合成样例的原区分；没有在新模块中新增永久硬编码的生产／成功状态。原身份切换、会话清理与锁定工作区约束保留。

## 实际验证

### 浏览器

`tests/frontend_workspace_rebuild_browser.js` 的结果记录于 [browser-rebuild-final.json](evidence/workspace-rebuild-20261104/browser-rebuild-final.json)。

- 服务、资源、协同分别检查 1280×800、1440×900、1920×1080；详情额外覆盖 1024、375、320 CSS px。没有页面横向溢出。
- 目录失败后保留目标，目标仍属于原创建表单；原资料读取与创建语义分离。
- 资源约束可见；完整长名称可键盘打开，返回恢复选择框焦点；数量变化同步草稿，已选占位不增加。
- 分类键盘导航、未读状态、过滤无匹配、成功空结果、加载失败分开验证；范围与计数没有扩大为全部待办。
- 从原列表实际点击进入详情，左侧使用精简列表，右侧主体没有内部卡片滚动；窄窗切为独立详情，返回走原导航守卫。
- 材料／记录切换、阅读面板及 Escape 回焦通过；完整来源元数据可读。失效读取下审核仍禁用。
- 工作区锁定标记不会被新详情布局覆盖；权限拒绝后表单、目录、约束与摘要清理，原占位按钮禁用。
- 减少动态与强制颜色条件下基本路径可用，未将这些局部检查说成完整 WCAG 审计。

`tests/frontend_resource_precheck_browser.js` 单独使用原预检处理器及合成只读 POST 回包，结果见 [browser-precheck.json](evidence/workspace-rebuild-20261104/browser-precheck.json)：预检可用时仍“尚未占位”、组合为 0；编辑使资格失效；容量不足时不能占位。仅两个 `/preview` POST，没有 `/holds`、确认或释放请求。

另做 125% 等效视口/DPR 模拟：1024×640 CSS px、DPR 1.25，对应 1280×800 图像；首页与资源无横向溢出，资源输入框仍为 42 CSS px。见 [缩放截图](evidence/workspace-rebuild-20261104/resource-scale125.png)。这不是修改 Windows 系统缩放后的原生验收。

### 代码、装配与构建

- 六组既有 DOM/回调脚本通过：`frontend_day_dom`、`frontend_day_advanced_dom`、`frontend_usability_dom`、`frontend_motion_dom`、`frontend_contract_adapters_dom`、`frontend_calendar_escape_callback`。它们主要保护原内联展示及业务绑定；新外部模块另由上述浏览器集成验证。
- 修正旧 DOM 测试以结束标记抽取第一段内联脚本，避免新增外部 script 标签被误当作 JavaScript；未减少原断言。
- Python 保留、预览 HTTP、契约测试合计 7 passed、6 skipped、3 subtests passed。6 个跳过项要求明确的 Windows test-owner DSN；不计通过。
- `node --check src/parkweave/workspace_design.js`、Python `compileall`、`git diff --check` 通过。项目无 TypeScript/独立类型检查配置，没有声称执行了不存在的类型检查。
- 使用声明的 `setuptools==80.9.0` 完成离线 wheel 构建。核对 wheel 中两个 HTML、共享 CSS/JS 和 PNG 与当前源文件字节一致。构建散列与验证信息见 [verification.json](evidence/workspace-rebuild-20261104/verification.json)。

## 未验证范围

没有在真实数据库和四个真实账号上执行完整的创建、补正、审核、占位、确认、取消、释放、外部受理或履约链路；Windows EXE/WebView2 未重新编译或实跑。真实 Windows 缩放、系统字号放大、读屏器以及其他浏览器未完整验收。当前结果是前端结构、状态呈现和原处理器绑定的实机验证，不是完整产品业务验收。

## 复现入口

运行 `python -X utf8 scripts/frontend_polish_review.py --seconds 600`。服务只绑定本机，最多运行 1800 秒；8876 正常只读样例，8877 空，8878 失败，8879 拒绝，8880 是旧 main 基准。当前页面加载新增的同源 CSS/JS；所有真实写请求仍由只读服务拒绝。浏览器测试文件是供 Playwright 浏览器工具执行的 async 函数，mock 场景在文件中明确标注。
