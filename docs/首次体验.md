# 首次体验 ParkWeave

当前可运行的是 Linux 云环境中的合成工程演示。Windows 启动脚本已准备，但尚未在 Windows 机器上运行；以下本地体验由安装者完成原生验证后交给使用者。它不是已经通过验收的一键安装包。

## 使用者：先完成一条本地记录

1. 请安装者给你本机访问地址和合成测试会话。会话不要发到聊天、截图或代码仓库里；不需要模型密钥。
2. 在浏览器打开安装者提供的地址，通常为 `http://127.0.0.1:8765`。页面应显示“合成工程验证 · 未接入真实园区或模型”。把合成会话填入“合成身份会话”。
3. 在“服务”输入一条测试诉求，例如“合成：咨询园区服务准备”，点击“创建本地办理记录”。
4. 点击“协同”→“查看持久状态”。当前成功只表示建立本地待补件记录；不表示政府受理、资源预约或线下办结。“资源”页目前是能力范围说明。
5. 刷新网页后需要重新输入会话。关闭网页不会停止后台；停止后台请安装者运行 Stop。再次启动会读取原数据库，不重新创建账号或覆盖记录。

没有收到访问地址、会话或数据库准备确认时，请先找安装者；不要猜连接信息、复制别项目会话或输入真实企业资料。本轮无真实模型预算，不需要开通模型调用。

## 安装者：Windows 候选流程，NOT_RUN

准备独立目录中的本仓库、获授权的 Python3.12 x64、本机 PostgreSQL Windows服务，以及既有专用 `parkweave` 数据库/`parkweave_app` 最小应用角色。版本/服务PID/数据路径/安装来源由原生实测记录；Linux Python3.12.14与PG16.2不是Windows版本锁定。脚本不安装数据库、不创建持久凭据、不下载解释器。

由批准的本机会话注入提供 `PARKWEAVE_OWNER_DSN` 与 `PARKWEAVE_DSN`：两者只连接 localhost 的 parkweave；后者必须是既有低权限 parkweave_app。不要把密码写进脚本/配置JSON/聊天；脚本不从隐藏文件找配置。需要测试时另提供 `PARKWEAVE_TEST_OWNER_DSN`，仅指向 localhost 的维护库 postgres、允许创建临时测试库的已授权账号。它不重置实际 parkweave 数据库。

在仓库目录打开 PowerShell，逐条执行，遇错停止查看提示：

```powershell
.\scripts\windows\Doctor.ps1 -Python '已批准的Python可执行文件路径'
.\scripts\windows\Setup.ps1 -Python '已批准的Python可执行文件路径'
.\scripts\windows\Doctor.ps1
.\scripts\windows\Start.ps1
.\scripts\windows\Status.ps1
# 完成浏览器体验后：
.\scripts\windows\Stop.ps1
# 需要完整工程回归且已注入隔离测试配置时：
.\scripts\windows\Test.ps1
```

示例路径文字需要替换为安装者实际提供的文件路径。不要绕过系统脚本签名/执行策略；若策略拒绝，交由安装者按已有授权流程审查签名，脚本不会关闭策略或防火墙。Setup创建独立 `.venv-windows`，使用候选依赖；已有配置直接拒绝覆盖，已有环境不静默重装。失败后不删除已有环境/数据库/会话，安装者检查不完整状态后决定下一步。

新建私有 `.runtime` 设置仅当前用户的私有继承ACL；既有目录只检查、不修改。若提示ACL不安全/不可读，请安装者明确评估并调整该项目目录，不能默认替用户修权限。Doctor读取现有ACL；本轮Windows ACL执行NOT_RUN，POSIX0700不能证明Windows安全。原生文件读取backend仍关闭，不能把文件下载在Linux通过推定Windows可用。

Start只绑定127.0.0.1，不提供手机远程入口。Status显示本项目登记PID；Stop仅终止命令、工作目录、创建时刻都匹配的ParkWeave API/worker，遇PID复用/其他项目拒绝；不停止PostgreSQL服务或删除数据。关机停止本地进程，重新Start后按数据库状态恢复，不宣称撤销已经发生的外部效果。

## 安装者核对与问题处理

- 页面打不开：先看Status和私有`.runtime/windows-services.log`；端口占用时脚本拒绝启动，不杀占用者。不要改为0.0.0.0或开放公网。
- 授权拒绝：确认会话来自这个ParkWeave配置且当前未撤销。Setup/seed不恢复撤销Grant，也不靠改客户端角色放行。
- 已有配置：使用Doctor/Start；不要重新Setup、删数据库或覆盖会话。原生依赖冻结在Doctor输出中记录，候选清单未实测不能叫Windows精确锁。
- 原生PG门：安装者需记录Windows服务名称、运行PID、实际postgres.exe/pg_ctl.exe路径和数据根。localhost连接也可能转发到WSL，SQL版本输出本身不足以证明Windows服务；本轮该门NOT_RUN。
- 测试汇总：工程子集PASS与完整36AT/6EX状态分列。离线模型、Linux AST和窄屏模拟不能替代真实书生链、Windows或手机实机验收。

跨平台目标为响应式网页；Mac本地后端与Android/iOS实机需单独验证。手机不运行本项目数据库，不承诺原生App，本轮不部署公开网址。
