# 首次体验 ParkWeave

当前可运行的是 Linux 本机合成工程演示。Windows 启动脚本已准备，但尚未在 Windows 机器上运行；Windows 候选流程见下文，不能据此称为已验证的一键安装包。页面模型策略为 LOCAL/MOCK：不调用真实模型、不需要模型密钥，R4保持关闭；F1尚未签收。

## Linux 安装者：启动合成演示

仓库已准备好 Python/Linux 测试依赖后，在仓库目录前台启动隔离的合成数据库、API和worker：

```bash
.venv/bin/python scripts/linux_fixture_server.py --preparation-fixtures --resource-fixtures --combination-fixtures --receipt-fixtures
```

这条命令仅用于Linux本地工程体验，监听 `127.0.0.1:8765`；首次启动会创建私有 `.runtime` 合成状态及随机会话。不要复制或公开会话文件。它不接触真实园区资料、生产数据库或真实模型。已有会话若被撤权，不会由fixture重新激活。

## 演示者：按角色走一条本地协作链

先打开 `http://127.0.0.1:8765`，使用本地 `.runtime/synthetic-sessions.json` 中企业 `fixture-a` 会话登录。不要把会话填入命令、文档、聊天或截图。页面会话只在当前页面内存中；切换身份会清空当前私有视图，刷新后需重新输入。

1. 在“服务”查看可选服务与专员，填写新的合成目标并开始资料准备。企业追加“诉求摘要”和“材料目录”两项资料，注明合成来源及版本。
2. 切到“协同”，换用 `.runtime/preparation-sessions.json` 中对应的 `prep-specialist-fixture-a` 合成会话，打开该事项并要求补正。切回企业会话，追加修订材料；再切回专员会话，人工核对当前资料包。最后企业切回并确认本地资料准备。
3. 切到“资源”，查看合成目录；选择两个不同资源，分别预检并创建短期占位，然后在本人占位列表选中两条并确认组合。回到资料事项，查看并明确关联已确认组合；重开资料、重新核对和确认后，显式重新核对Case资源关联。
4. 执行者步骤需要测试owner为这个新合成Run准备既有合法Run assignment。此准备在产品UI之外完成；产品不会自动给执行者授权，也没有通用assignment写入口。没有该前置时，执行者回执及相应协同操作应阻塞，不要绕过权限。
5. 专员可从事项查看内部分派并选取已有合法执行者；执行者本人切换到 `.runtime/receipt-sessions.json` 中对应的 `receipt-executor-fixture-a` 会话并接受事项。执行者提交合成回执后，企业可要求纠正或重开；这两种操作后，执行者都须重新提交当前回执版本，企业再核对该版本，直到状态为 `LOCAL_ACKNOWLEDGED`。协同区的分派通知可分别查看、请求打开并明确标记已读。
6. 只有企业核对当前回执后，才能在“查看此Case的本地关闭与重开记录”逐项检查依赖、重新校验当前一轮并关闭本地记录。关闭前Case为 `NEEDS_INPUT`；本地记录关闭后真实Case状态为 `WAITING_CONFIRMATION`；显式重开后状态为 `REOPENED`，新一轮需要再次校验。以上状态都不表示原目标完成。回到“资源”显式整组取消组合，释放本地合成容量。

预期可观察结果是资料、资源、分派、回执、通知和Case本地记录带有持久历史，刷新后重新读取仍在；身份/租户隔离和当前授权仍生效。回执与本地关闭不代表真实目标完成；Case仍可能是 `NEEDS_INPUT`，资格为 `NOT_EVALUATED`，外部受理为 `NOT_SUBMITTED`，线下履约为 `NO_EVIDENCE`。执行者Run assignment需显式fixture前置，因此该体验不证明无需准备的新企业冷启动、完整AT35或完整V1验收。

## Linux浏览器复现脚本（可选）

以下脚本需要已运行上述同一合成harness、仓库已有获准缓存的 agent-browser 0.38.2 与 Chromium；脚本不会自动联网安装依赖。每次使用新的报告路径和截图目录：

```bash
.venv/bin/python scripts/preparation_browser_smoke.py --report .runtime/preparation-demo.json
.venv/bin/python scripts/case_resources_browser_smoke.py --report .runtime/case-resources-demo.json --screenshots .runtime/case-resources-demo
.venv/bin/python scripts/dispatch_notices_browser_smoke.py --report .runtime/dispatch-notices-demo.json --screenshots .runtime/dispatch-notices-demo
.venv/bin/python scripts/controlled_plan_browser_smoke.py --report .runtime/controlled-plan-demo.json --screenshots .runtime/controlled-plan-demo
.venv/bin/python scripts/case_lifecycle_browser_smoke.py --report .runtime/case-lifecycle-demo.json --screenshots .runtime/case-lifecycle-demo
```

第二至第五个脚本还要求通过已批准的本机会话显式提供 `PARKWEAVE_RECEIPT_FIXTURE_OWNER_DSN`（Case资源/回执）、`PARKWEAVE_DISPATCH_FIXTURE_OWNER_DSN`（分派/通知）或 `PARKWEAVE_CASE_FIXTURE_OWNER_DSN`（四步计划/Case生命周期），且只指向本次隔离的合成测试数据库，用于为新Run准备既有assignment。这里仅列变量名，不应把DSN值写入文档、命令历史或聊天。Case生命周期脚本复验初次回执未经企业核对时关闭被阻止、企业核对至 `LOCAL_ACKNOWLEDGED` 后可校验/关闭、Case重开后再次显式校验及reload持久状态；它没有覆盖回执纠正/重开后的再次提交。四步计划脚本只验证计划检查点，不代替Case关闭流程。脚本范围各有侧重，不是完整V1验收套件；报告会明确列出模型调用为0、R4关闭、F1未签收及Windows/全量AT/EX未运行。

演示结束时在运行harness的前台终端按 `Ctrl+C` 正常停止本次API、worker和临时测试数据库。关闭浏览器标签不会停止后台。不要用 `Stop.ps1` 停止Linux harness；Windows脚本只用于下述Windows候选流程。

## 使用者：先完成一条本地记录

1. 请安装者给你本机访问地址和合成测试会话。会话不要发到聊天、截图或代码仓库里；不需要模型密钥。
2. 在浏览器打开安装者提供的地址，通常为 `http://127.0.0.1:8765`。页面应显示“合成工程验证 · 未接入真实园区或模型”。把合成会话填入“合成身份会话”。
3. 在“服务”输入一条测试诉求，例如“合成：咨询园区服务准备”，点击“创建本地办理记录”。
4. 点击“协同”→“查看持久状态”。这条入口只建立本地待补件记录；资料准备、资源、协同工作区还提供上述合成流程，不代表真实园区受理、预约或线下办结。
5. 刷新网页后需要重新输入会话。关闭网页不会停止后台；停止后台请Linux演示者在harness前台按 `Ctrl+C`。再次启动会读取本地数据库状态。

没有收到访问地址、会话或数据库准备确认时，请先找安装者；不要猜连接信息、复制别项目会话或输入真实企业资料。本轮无真实模型预算，不需要开通模型调用。

## 安装者：Windows 候选流程，NOT_RUN

准备独立目录中的本仓库、获授权的 Python3.12 x64、本机 PostgreSQL Windows服务，以及既有专用 `parkweave` 数据库/`parkweave_app` 最小应用角色。版本/服务PID/数据路径/安装来源由原生实测记录；Linux Python3.12.14与PG16.2不是Windows版本锁定。脚本不安装数据库、不创建持久凭据、不下载解释器。

由批准的本机会话注入提供 `PARKWEAVE_OWNER_DSN` 与 `PARKWEAVE_DSN`：两者只连接 localhost 的 parkweave；后者必须是既有低权限 parkweave_app。不要把密码写进脚本/配置JSON/聊天；脚本不从隐藏文件找配置。需要测试时另提供 `PARKWEAVE_TEST_OWNER_DSN`，仅指向 localhost 的维护库 postgres、允许创建临时测试库的已授权账号。它不重置实际 parkweave 数据库。

在仓库目录打开 PowerShell，逐条执行，遇错停止查看提示：

```powershell
.\scripts\windows\Doctor.ps1 -Python '已批准的Python可执行文件路径'
.\scripts\windows\Setup.ps1 -Python '已批准的Python可执行文件路径'
.\scripts\windows\Doctor.ps1
.\scripts\windows\Start.ps1
.\scripts\windows\Status.ps1
# 完成浏览器体验后：
.\scripts\windows\Stop.ps1
# 需要完整工程回归且已注入隔离测试配置时：
.\scripts\windows\Test.ps1
```

示例路径文字需要替换为安装者实际提供的文件路径。不要绕过系统脚本签名/执行策略；若策略拒绝，交由安装者按已有授权流程审查签名，脚本不会关闭策略或防火墙。Setup创建独立 `.venv-windows`，使用候选依赖；已有配置直接拒绝覆盖，已有环境不静默重装。失败后不删除已有环境/数据库/会话，安装者检查不完整状态后决定下一步。

新建私有 `.runtime` 设置仅当前用户的私有继承ACL；既有目录只检查、不修改。若提示ACL不安全/不可读，请安装者明确评估并调整该项目目录，不能默认替用户修权限。Doctor读取现有ACL；本轮Windows ACL执行NOT_RUN，POSIX0700不能证明Windows安全。原生文件读取backend仍关闭，不能把文件下载在Linux通过推定Windows可用。

Start只绑定127.0.0.1，不提供手机远程入口。Status显示本项目登记PID；Stop仅终止命令、工作目录、创建时刻都匹配的ParkWeave API/worker，遇PID复用/其他项目拒绝；不停止PostgreSQL服务或删除数据。关机停止本地进程，重新Start后按数据库状态恢复，不宣称撤销已经发生的外部效果。

## 安装者核对与问题处理

- 页面打不开：先看Status和私有`.runtime/windows-services.log`；端口占用时脚本拒绝启动，不杀占用者。不要改为0.0.0.0或开放公网。
- 授权拒绝：确认会话来自这个ParkWeave配置且当前未撤销。Setup/seed不恢复撤销Grant，也不靠改客户端角色放行。
- 已有配置：使用Doctor/Start；不要重新Setup、删数据库或覆盖会话。原生依赖冻结在Doctor输出中记录，候选清单未实测不能叫Windows精确锁。
- 原生PG门：安装者需记录Windows服务名称、运行PID、实际postgres.exe/pg_ctl.exe路径和数据根。localhost连接也可能转发到WSL，SQL版本输出本身不足以证明Windows服务；本轮该门NOT_RUN。
- 测试汇总：工程子集PASS与完整36AT/6EX状态分列。离线模型、Linux AST和窄屏模拟不能替代真实书生链、Windows或手机实机验收。

跨平台目标为响应式网页；Mac本地后端与Android/iOS实机需单独验证。手机不运行本项目数据库，不承诺原生App，本轮不部署公开网址。
