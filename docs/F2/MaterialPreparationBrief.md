# 企业明确选用事实到可复核诉求摘要

本切片对应原产品 §5.3、F2-T01/T02 的材料准备和 AT23/AT35 的部分工程要求。企业不必把已为本事项明确选择的地区、员工人数、服务诉求再次手抄到材料中：服务器结合当前企业诉求整理实际摘要正文，企业检查全文及原获派专员后明确分享，保存为原材料系统的一个新 `need_summary` 版本。它不是接单存在性报告，也不是政策条件、真实证明或办理完成。

当前服务仍是 `synthetic-material-preparation@1`，无资格条件；准备度规则仍 `ENGINEERING_ONLY / DRAFT / business_publication=False`。本切片只整理企业自述，不提取或发布新政策，不猜测财务、资质、签章、证明或承诺。材料目录仍由企业提供，其真实政策要求须有合法来源另行明确。缺失、未选和失效事实保持缺口。

## 当前产品入口

使用 [现有临时体验](CurrentRestrictedExperience.md) 的合法企业、原专员身份和新事项。无需新增 Grant、数据库修改或 JSON 命令。访问桥和接单报告的真实启用仍关闭；这个摘要流程不要求申请执行者访问或生成接单报告。

1. 企业从服务入口创建新资料准备事项，追加自己的三项合成事实来源，在本事项明确声明用途并逐项选择当前来源。竞争来源须由企业明确选择；不能由系统猜测真实值。
2. 在资料详情点击“查看当前来源的摘要草稿与待补材料”。全文包括当前企业诉求及所选三项自述的实际值、单位、来源版本和指纹；缺材料与专员补正列在旁边。
3. 检查全文和具名的原获派专员。勾选明确分享，再点击“明确追加此摘要为新未核验版本”。保存请求只提交来源 hash、事项版本、接收人及确认；客户端不能替换服务器正文。
4. 在原材料输入框提供本人材料目录。新摘要/目录仍是未核验材料；逐项补正必须提交所需新版本，生成摘要不自动解决目录补正。
5. 切换到原获派专员，在本人资料列表打开同一事项，检查精确当前全文及版本，再按原 REVIEW 核对。企业再按原 CONFIRM 确认。刷新后能读取实际持久材料及历史。

结果未知时，只使用页面原请求重试。提交成功而回读失败时，摘要、旧材料、清单与接收人投影隐藏；普通刷新、另一个摘要、人工材料、事实写入、材料准备度写入和同身份离开当前事项被阻止。重试复用原 key、正文和事项，先读取精确 evidence ID/正文 hash 的事件证明，再恢复界面。切换身份会清除私有视图；不能以此推断前一次写入失败。

## 来源、审核与历史

草稿读取不写数据库。只有显式分享才同事务追加原 `preparation_evidence`，更新原事项版本/补正提交，失效原计划并写原 `ADD_EVIDENCE` 事件。没有新表、迁移、角色、权限或安装操作；没有模型或外部数据传输。新材料来源为 `USER_STATEMENT`、真实性 `UNVERIFIED`。

原企业/Run/tenant/字段用途权限和精确合成服务范围先于读取与幂等恢复检查。分享 hash 绑定当前事实选择及其 authority/source、当前诉求、材料、补正、服务来源、原专员及其当前 READ/REVIEW_ASSIGNED。所选值和来源指纹进入企业明确分享的正文；未选值与私有来源摘录不进入摘要，事件只保留允许的材料 ID/hash 等证明。

事实、服务、分享对象或相关权限来源改变后，原生成摘要只留历史。新的事实确认和重新授权不能自动让旧正文成为当前；已标记摘要的来源门会阻止原 REVIEW/CONFIRM、P1/P5 和准备度采用旧生成正文。企业须重新查看、分享新正文，再让专员核对；原人工新材料仍按既有合同处理，不冒充服务器生成摘要。新输入回归必须核对正文实际变化，不只核对 hash。

保存前采用原 CAS 和来源 hash；同键或不同键并发只能有一个对应来源版本的实际追加。新入口为后续独立 REVIEW/CONFIRM 预留版本容量；已知还需目录提交/补正时再预留一版。保留原有有界历史，不提高上限；后续额外修改仍可能消耗容量。

所有写入/事件后再次核对事实时效、目录和接收人来源。过期、写入异常或不匹配会回滚该事务。目录只有 SELECT 权限，因此使用末段重新读取比较，不增加 UPDATE Grant。末次读取到 COMMIT 仍有时间窗口；无修订或不遵循现有锁协议的管理员直接改动不是可保证永久观察的撤销历史。本切片不宣称所有外部动作的提交瞬间线性化。

## 验证与范围

当前候选的定向 JUnit、实际 collection、加载来源、冻结 hash、真实浏览器和独立 API 输出另见 [机器证据](../integration/MaterialPreparationBriefEvidence.json)。历史 `a1e6022` 的 2422 PASS 完整 Linux 只属于上一冻结源码；不能作为本切片完整回归。首轮目录锁权限失败、错误读取私有账本的测试失败以及后续修正均保留。

本切片定向业务/消费端 360 PASS（含 22 项新用例，186.33 秒），元数据 171 PASS（5.20 秒），分别保留范围。2453 项仅为当前收集结果。全新合成浏览器流程 PASS，15 张截图、两次同键 POST 一版摘要和独立 API 全文/hash 回读已保存。独立只读复核无实质阻断；320 预览正文位于截图下方，专员/确认截图没有展示正文与确认详情，精确 REVIEW/CONFIRM 依据 driver 和独立 API 回读。503 为实际服务器 200 后的客户端注入。新摘要不复用历史完整回归的签收结论。

本成果是企业确认分享的未核验诉求摘要和现有材料待办，不是正式政策材料包、完整 PR0 或业务资格结论。Case 保持未完成，外部受理 `NOT_SUBMITTED`、线下履约 `NO_EVIDENCE`。F1 未签收/F2 并行，R4 关闭/模型预算 0；Windows Server 工程 CI 不替代 Win11 原生验收。原环境和备份保留。
