# ENG098：审核候选模板与新企业冷启动

基线为 `f34b28b`。本片沿原 V1 §5.2、§7.5 处理模板与业务实例分离：审核后的参数结构及注册步骤固定为候选发布快照，新企业使用自己的当前身份、新诉求和新材料创建新的 Run / Case / Preparation。ENG097 的材料补正冷会话不计为模板冷启动。

## 实现边界

`template_candidate.py` 是默认关闭的独立 SQLite 合同。作者、审核者、候选发布者使用三个独立测试主体，不推断或扩大生产角色的审批权。内容版本固定参数 schema、注册 P1–P5 依赖闭包、目标覆盖、合成来源及有效期；不可变发布快照绑定来源、定义、注册表、审核及当前合同的 SHA256。来源版本不可覆盖，较新来源版本使旧发布不可用；修改须回到草稿并重新审核。来源 head 按园区 / source_id 共享：获准修改同一来源的候选作者可使其他引用它的候选暂时不可用。正式启用仍需定义来源维护主体与范围，不能从隔离作者权限推断生产来源发布权。撤回、过期或当前合同失效拒绝新消费。合同 head 在独立候选 SQLite 中不可变追加，版本严格递增；同合同可重新打开，旧合同不能在重启或另一活跃引擎中恢复旧发布。候选 schema v2 对旧/不完整数据库拒绝，不自动改写历史文件；生产 PostgreSQL schema 仍为 23。

`template_consumer.py` 只在显式批准的本地 `fixture_<UUID>` 数据库与新企业范围启用。每阶段重验原 Bearer 主体、READ / EXECUTE / PREPARE、case.create 和获派专员权限。调用原 Run、资料、诉求与注册步骤 service，普通生产 app 不挂载候选路由。企业范围由服务端身份决定，输入不能指定组织、旧 Case、旧材料引用或 Grant。

消费日志记录不可变实例绑定以及每阶段原请求 body hash / key。Run 在原 worker 完成前保持 PENDING；后续阶段具有真实事务结果。结果未知时用原键及原正文恢复，不将多事务流程称为原子完成。确定拒绝记为 REFUSED / BLOCKED；已提交但日志确认失败返回 503 UNKNOWN。候选发布撤回后原实例历史保留，不自动迁移或撤销已有业务操作。

浏览器入口 `/template` 只在独立组合工厂出现；原产品 `/` 继续处理获派专员 REVIEW、企业 CONFIRM 和 P1 VERIFY。令牌与未知请求仅存内存，身份或模板范围切换清除私有状态；迟到响应不覆盖新上下文。未知回执的页面重试仅保证同页原键/原正文；完整重载不会恢复该页面键。后端提供仅本人、批准组织和数据库范围的实例列表，页面目前支持已知实例 ID 的只读恢复，不宣称未知键重载恢复。

## 正式启用仍待确定

生产模板作者、独立审核者与正式发布主体及其职责分离尚未签收。正式目标应限定到确切园区、模板、服务和适用组织范围；最小能力分别为草稿提交、审核与该对象的发布/撤回。不能借用生产 resource_admin 或历史规则候选的权限推断此授权。

模板消费者只使用现有企业 Case 创建、资料准备及获派专员审核能力；模板不新建身份、Grant、Run assignment，也不自动判断资格或履约。本片隔离候选证明不替代 T06 / AT-08 / AT-35 的正式发布验收。F1 未签收，F2 仅并行工程；R4 关闭，模型调用与预算均为 0。

## 验证记录

当前状态与原进程核对保存在 `.runtime/eng098-start-state.json`。初次候选专项在默认沙箱遇到本地 socket bind EPERM；同操作正式权限流程后可运行隔离 PostgreSQL。首次实际候选结果为 21 PASS / 1 FAIL：新增测试用泛化 `/template` 子串错误匹配已有合法路由，现已按精确新命名空间修正。最终模板专项为 66 PASS / 0 FAIL / 0 ERROR / 0 SKIP / 2 WARN，12.10 秒。首次合并专项另有旧路由误匹配、UUID 顺序断言和原 Denied 审计行比较失败；这些测试期待已分别修正为精确命名空间、证据成员关系及拒绝审计与业务零写分离，原日志保留，不删业务用例或增加跳过。

最终真实浏览器 1 PASS / 36.27 秒：两个真正新企业、两个冷会话、三个新 Run / Case / Preparation、六份新材料、三个不同稳定 P1 步骤。经过独立候选审核发布、原获派专员人工 REVIEW、企业 CONFIRM、P1 VERIFY。实际验证提交后丢回执同页同键恢复、跨组织 403、迟到身份响应隔离、撤回拒绝新建且不生成第四 Case、旧实例绑定及重载已核验 P1 历史保持。七张权限/身份表摘要和两份合同 SHA 前后相等，无新 assignment、模型或浏览器启动后的 setup 写入；自有 API/worker 均停止。三次浏览器 PASS 保留，前两次仅因后续实际产品源码修正重测，不作为最终同源结论。

当前完整 collection 为 1968 项 / 72 文件，四片 529 / 459 / 488 / 492；全局与四片真实稳定 keys 多重集精确一致，ENG097 的 1826 个旧 keys 全部保留。894 个 AST 诊断 ID 及所有测试/实现 hash 刷新；collect-only 不等于运行通过。最终完整 Linux 回归为 **1959 PASS / 0 FAIL / 0 ERROR / 9 native SKIP / 2 WARN，472.16 秒**；1968 项 JUnit 与 collection 相符，262 个冻结源码文件零差异。全部九图、14 项产物及源码已由独立审阅者实读核验，无阻断。专项不重复计入全量，机器证据见 [eng098-template-cold-start.json](evidence/eng098-template-cold-start.json)。
