# 当前受限体验：从干净环境开始

本指南对应冻结提交 `a1e602238606d4e20c0a42e4dbb5be900113675f` 的实际命令和页面。当前可体验的是本机合成事项、限定 Run 访问、原角色交接，以及服务器生成的本地合成报告。报告和企业核对都不证明资格通过、外部受理、线下履约或 Case 目标完成。

## 选择启动方式

| 方式 | 可使用的入口 | 数据与身份 |
| --- | --- | --- |
| 普通 `parkweave.api:configured_app` | 当前身份已有合法权限的原业务入口；单 Run 申请、审批和本地报告适配器未启用 | 使用负责人已经配置的既有数据库和身份；启动不创建凭据、不修复授权 |
| 下方三个显式开关的隔离体验 | 合成新事项 → 限定访问申请与独立审批 → 原分派与本人接单 → 本地报告 → 企业核对 → 撤销 | 本次新建的私有临时数据库与合成身份；启动时没有 Run、Case、资料事项、分派、回执或 Run assignment |

要从零体验完整的受限流程，使用第二种方式。启动器的可信合成初始化和页面中的用户申请、独立批准是两个不同阶段：前者仅准备本次测试身份、原目录和资源；它不预先批准任何 Run，也不代替用户操作。

## 准备与启动隔离体验

需要 Linux、Python 3.12、项目依赖及 `linux-test-db` 可选依赖（`pgserver`），以及可使用的本地临时目录和空闲的回环端口。普通手动体验只需自己的浏览器，无需 `agent-browser`、缓存 Chromium、模型凭据或外部服务。

在仓库根目录操作，先激活已有项目虚拟环境；若需要安装依赖，按本地环境的正常安装流程准备，例如 `python -m pip install -e '.[linux-test-db]'`。不要更改或覆盖旧环境备份、旧会话文件或既有数据库。

```sh
cd <仓库根目录>
source <已有项目虚拟环境>/bin/activate
PYTHONPATH=src:. python -m scripts.isolated_run_access_demo \
  --enable-isolated-run-access \
  --fresh-fixture \
  --enable-isolated-local-execution \
  --port 8765 \
  --max-seconds 3600
```

保留此终端。`--enable-isolated-run-access` 和 `--fresh-fixture` 必须同时提供；第三个开关才启用本地报告。端口范围为 1024–65535，运行时限为 1–28800 秒。若 8765 已占用，选择另一个空闲端口，不停止不属于此次体验的服务。

启动器等待最多约 15 秒确认 API 就绪，然后输出不含令牌或 DSN 的 JSON：包括 `port`、`runtime_directory`、`api_pid`、`worker_pid`、两个启用状态及 `initial_business_counts`。这些业务计数应全为零。API 与创建证据在启动器同一进程中；原 `LOCAL` worker 是单独的本次子进程。

打开 `http://127.0.0.1:8765/`（改端口时相应修改）。也可在浏览器打开 `/health`，核对其 `process_id` 等于本次输出的 `api_pid`，并显示 `schema: 25`、`data: SYNTHETIC`、`execution_mode: LOCAL`。不要把另一个服务的健康响应当成本次启动成功。

## 取得本机合成身份

在输出的 `runtime_directory` 中，用本机私有编辑器查看以下文件，按 JSON 键找到对应令牌。将令牌只粘贴到页面顶部的“合成身份会话”密码输入框；不要通过终端打印、命令行参数、截图、公共文档或上传文件分享令牌。

| 文件 | 本流程使用的键 | 用途 |
| --- | --- | --- |
| `synthetic-sessions.json` | `fixture-a` | 企业经办人，创建和核对自己的事项 |
| `preparation-sessions.json` | `prep-specialist-fixture-a` | 获派专员；此次隔离配置另行明确列为访问审批人 |
| `receipt-sessions.json` | `receipt-executor-fixture-a` | 既有合成执行者，初始只有同租户 READ，没有任何 Run assignment |

其余 `fixture-b/c` 身份属于其他企业或园区，不能代办这个事项。`fixture-info.json` 同样含私有令牌，供本机体验工具查找；`smoke-environment.json` 是启动元数据，`worker.log` 是私有 worker 日志。不要公开整个临时目录。

页面会话仅在当前页面内存中保留。切换身份会清空当前私有界面；这是模拟不同主体，不代表企业获得专员或执行者的权限。

## 在页面完成一次新事项

以下步骤始终使用同一个新 Case、Run 和资料准备编号。记下这些非令牌编号，以及报告的执行编号和内容 SHA256，供刷新后核对。

1. **企业创建。** 输入 `fixture-a` 令牌，在“服务”点击“查看可选服务与专员”，填写一个明确标注合成测试的资料整理目标，选择 `prep-specialist-fixture-a`，点击“开始资料准备”。这个入口建立真正的新 Run 和 Case，由原 worker 推进后创建资料事项；不要再用“创建本地办理记录”另建第二个 Run。等待资料详情出现，再记录编号。
2. **企业补充当前事实与材料。** 在该资料详情的“从本人原事实入口追加合成来源”中，分别补充地区、员工人数、服务诉求的合成自述，填写来源编号、版本、摘录和有效 UTC 时段，并明确资料准备用途。随后“查看本事项事实来源与用途”，明确声明本事项用途，逐项选择当前可用来源，再明确记录本次用途与来源。追加“诉求摘要”和“材料目录”两个材料槽的新内容及来源版本。来源选择与材料均保持未核实真实性；不要采用过期来源或把不同自述自动视为一致。
3. **原专员审核，企业确认。** 切换到 `prep-specialist-fixture-a`，在“协同”→“我的资料准备事项”打开同一事项，填写说明并“核对本地资料包”。再切回 `fixture-a`，重新打开同一事项，填写说明并“确认本地资料准备”。应显示本地资料确认状态；发生补正时，先按要求追加新版材料，再让专员重新核对。
4. **企业 REQUEST。** 在“协同”打开“单 Run 访问状态与审批”，填写上述精确 Run 编号并读取状态。也可从该事项的 Case 协作入口进入。选择 `receipt-executor-fixture-a`，填写明确 UTC 起止时刻和申请原因，点击“提交单 Run READ 申请”。使用当前有效的短期限，例如约十分钟；批准期限不得超过申请范围、页面所示服务端上限或审批会话截止时间。`REQUESTED` 只表示待审，尚无实际 Run 访问。
5. **独立 APPROVE。** 切换到 `prep-specialist-fixture-a`，重新输入同一个 Run 编号、读取当前申请，核对企业、执行者、READ 和期限，填写独立审核说明，再“批准限定访问”。确认当前访问投影已实际应用；“决定已记录、投影待完成”仍不能作为可接单依据。专员能够审批来自此次启动的明确配置，不能从材料 REVIEW 推导审批资格。
6. **原 OFFER／本人 ACCEPT。** 专员回到同一资料事项的“内部分派”，从当前合法执行者目录选择 `receipt-executor-fixture-a`，填写说明并记录分派。切换到该执行者，在“协同”刷新本人分派事项，打开同一事项并本人接受。批准访问本身不等于接单。接受后，从当前接单事项进入它实际生成的回执步骤。
7. **执行者生成服务器报告。** 在当前回执详情填写“本次本地生成说明”，点击“生成本地合成接单报告”。报告正文由服务器适配器生成；不要在“人工填写的合成回执”里伪造报告或来源标签。成功后核对执行记录编号、适配器、Case／Run、资料版本和 SHA256；当前状态应为回执已记录、等待企业核对。该步骤以后要求适配器生成新版本，不能降级为人工提交。
8. **企业 ACK。** 切换到 `fixture-a`，刷新本人回执事项，打开同一当前回执，核对服务器报告摘要和来源 SHA256，填写企业说明，再点击“核对当前合成回执”。企业核对是独立动作；执行者不能替企业确认，确认也不会完成真实 Case 目标。
9. **企业 REVOKE。** 企业重新读取同一个 Run 的访问状态，填写撤销说明并“撤销当前访问”。执行者再读取该 Run 应被拒绝，刷新本人分派／回执列表也不应继续提供已失效访问。已有历史记录保留；撤销不自动删除报告、材料或企业核对历史。

上述报告路径不要求采用四步或持久步骤计划。若自行采用了计划，应按当前计划前置逐步核验；访问批准或报告生成不会跳过它的材料、资源及接单前置。

## 刷新、失败与结果未知

正常成功后可以冷刷新页面，重新输入自己的令牌，通过本人列表或精确 Run 编号重新读取服务端持久状态。当前角色只能读取自己的合法范围；旧页面内容不是授权证明。报告应仍是同一执行编号和来源哈希，而不是因刷新生成新版本。

若页面显示“结果未知”，保持当前身份和当前事项，使用“使用原请求重试并核对结果”。页面保存的是原正文和原请求编号；不要改写理由、再点新申请、切换角色或用新编号重发。已批准但投影待完成的申请，也应重试原请求；实际访问完成前不能继续接单。服务器报告已生成而回读失败时，旧快照会隐藏，原请求重试应恢复同一执行编号。

403 表示当前访问已拒绝，422 表示输入合同不满足，普通 409 表示版本、容量或当前依赖需重新读取；这些都不能通过修改数据库、补 Grant、伪造证明或重置计数绕过。若浏览器已关闭而原请求状态丢失，先重新读取当前历史和报告，核对原编号；无法确认时停止重复写入，交由负责人核查本机记录。不要把断网或没有看到响应当成“肯定未提交”。

期限到达、主体停用、证明失效或授权撤销后，原请求重试也必须通过当前权限检查。新一轮合法申请与批准会形成新租约，旧报告保持历史并失去当前验收资格；恢复访问不会自动恢复旧企业 ACK。由执行者明确生成新版本，再由企业核对当前版本。收到补正或重开要求时，也须走新版报告和企业核对。

## 停止与数据生命周期

在启动终端按 Ctrl-C，或等待 `--max-seconds` 到期；SIGTERM 同样请求停止。启动器对 API 采用约 12 秒等待加 3 秒强制退出请求，对精确 owned worker 采用终止等待 10 秒、必要时再等待 5 秒。随后停止本次 PostgreSQL，并在确认停止后删除仅此调用新建的临时目录。

因此本体验的资料、令牌、访问决定、报告和审计记录会随正常关闭删除。它不是持久用户产品，也不会创建可用于真实系统的新凭据。需要保留的脱敏编号或报告摘要应在关闭前由本机负责人记录；不要导出令牌。停止不能确认时，程序报错并保留临时目录，不应自行删除仍在使用的目录或终止其他进程。既有 `.runtime`、旧数据库及原环境备份保持原状。

## 普通配置与真实启用边界

已有负责人配置且兼容当前代码的环境，可在仓库根目录使用已设置的私有 `PARKWEAVE_DSN` 启动普通 API：

```sh
PYTHONPATH=src:. PARKWEAVE_MODE=LOCAL python -m uvicorn \
  parkweave.api:configured_app --factory --host 127.0.0.1 --port 8765
```

该命令不发现凭据、不迁移或初始化数据库，也不启用本指南的隔离访问桥与本地报告。已有合法身份可使用其原授权入口；缺失访问时保留阻塞。不要将临时测试身份、审批配置或创建证明复制到既有环境。

真实启用仍需独立可审计的主体与精确范围、现有合法授权、真实服务和执行合同、支持的安装／数据库创建证明，以及相应环境的单独审核与执行授权。当前 Linux 合成流程、测试通过和页面显示不能代替这些前提，也不构成 installed Windows 或生产启用步骤。本指南不执行真实启用。
