# ENG082 四步计划返回资料的角色与版本连续性

企业从已有回执进入四步计划再返回资料时，当前角色原先会丢失：真实浏览器复现 `prepRole=null`，企业追加资料入口隐藏，却显示专员核对按钮。现在返回导航保留当前授权角色与同Case版本，并能在读取期间取消，迟到成功或失败都不能恢复旧视图。基线 `d9078a88ca23d095430ed2cb328fc3d4c73c710f`，仅本地开发和commit，不迁移、恢复、覆盖或查询远端。

设计来源为总设计§3三工作区与实际角色使用、§5.5责任及回执核验、§5.6变化后明确重验，阶段 F2-T04/T07。完成的是当前已有合成Case的导航体验子集，不是全部角色协同、AT35、F2签收或真实履约。

## 源码与行为

`controlled_plans.py` 已有计划的授权只读投影增加当前 `preparation_revision`。这个整数让前端真正比较资料版本；此前该字段仅在尚未启用计划的响应中存在，已启用计划的比较会退化为 `undefined === undefined`。原鉴权、最小来源投影和命令权限不变，专员/执行者仍无企业来源细节或核对权限。

`web.html` 进入资料、分派或本地Case前，检查当前计划身份、代次、token、事项、计划ID、计划修订、资料修订及模板hash。返回资料只允许企业/获派专员，执行者继续没有资料入口。资料GET成功且版本与计划读取时捕获的版本一致后，才设置角色并展示当前事项控件；版本变化则要求返回计划刷新，不展示为旧计划已适用。全部业务命令继续绑定现有资料/API版本检查，导航本身不提交命令。

计划加载隐藏旧操作入口，显示正在读取且可收起；资料加载有独立可见“取消并返回此Case四步计划”。取消提升代次，再用当前身份读取同Case计划；收起由回执进入的计划保留该回执，由本地Case进入的计划则用当前API重新读回同Case。切角色、Case、工作区或重新进入后，旧资料/计划的迟到成功与403都不恢复旧页面，也不清除新计划。
