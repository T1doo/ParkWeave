# 同一合成资源的替代时段

原依据：`docs/sources/V1/平台产品设计 (2).md` §5.4（158–169行）要求资源紧张时在硬规则内展示替代时间/资源，使用数据库时钟、UTC半开区间、容量及缓冲，并区分预检、占位与确认。基线 `a954bf6811e395d7515181f8bad8dd8f12d1cd7c` 的单区间 `preview` 和原资源表单没有同一资源的时段搜索。本切片补齐时段搜索；已有资源组合替代保持原行为。

## 只读接口

`POST /api/synthetic-resources/{resource_id}/alternative-times` 是与原 `preview` 相同的只读预检，接受：

```json
{
  "starts_at": "2026-10-12T10:00:00Z",
  "ends_at": "2026-10-12T11:00:00Z",
  "quantity": 1,
  "search_from": "2026-10-12T10:00:00Z",
  "search_until": "2026-10-12T14:00:00Z"
}
```

- 同一已有授权 `SYNTHETIC / LOCAL_AUTHORITY` 资源；仅需要当前 enterprise READ 与租户资源 READ。无需 HOLD/EXECUTE，不创建新的权限。
- 原区间决定不变的时长（正数、最多4小时）和数量（整数1–20）；搜索窗口必须容纳该时长，正数、最多24小时。所有时间要求带时区，规范为UTC。
- 以 `search_from` 为网格锚点，每15分钟检查一个开始时间，候选结束不得超出 `search_until`。最多扫描100个候选（24小时窗口和正时长在此网格下实际最多96个，100为兜底上限），完整扫描当前有界网格后只返回最早10个可用时段，严格按开始时间升序。
- 复用当前授权锁、资源共享锁与锁后再次读取；数据库 `clock_timestamp()` 在获得资源锁后采样一次。复用原 `_window`、`_peak`：资源启用/权威来源/开放区间、当前候选双侧缓冲、既有占用自己的历史缓冲、峰值容量、半开边界。过期 HELD 不占容量，CONFIRMED 持续计入，不清理或改写记录。超出Python可表示日期范围的UTC转换返回422；无法表示双侧缓冲的候选不建议。
- 返回资源版本、状态时间、原区间/数量、搜索窗口、网格/扫描/返回上限、扫描数、可用候选数、截断标记和时段列表。覆盖范围为 `SEARCH_WINDOW_GRID_ONLY`。空列表仅代表所查网格没有找到可用时段，不能证明所有时间不可用。候选不包含他人身份、组织、占用原因或hold ID。
- 不使用幂等key，不写业务表、receipt、Case或outbox。建议不锁住未来容量，原 HOLD/CONFIRM 事务仍复核当前授权、规则和容量，之后被抢占会被原提交拒绝。

## 原表单

“查找替代时段”保留原时长和份数，显式提供搜索窗口，展示采样、截断和空结果边界。选建议仅填入开始/结束时间、清除旧预检并禁用占位按钮，不发送任何写请求。用户仍需重新预检，再明确占位和确认。

沿原 `resourceGeneration`、token和全部输入快照检查，身份/资源/时间/数量/搜索窗口变化或ABA切换会丢弃迟到结果；当前401/403清除当前资源私有视图。未定组合状态仍可只读搜索，原组合写入门禁保持。
