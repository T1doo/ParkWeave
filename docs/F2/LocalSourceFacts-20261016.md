## 使用方法

沿用[本地事项启动说明](LocalCaseEntry-20261016.md)，使用自己已完成 setup 的隔离目录执行原 `serve`。也可显式新建原固定合成初态；不能复制别人的目录、改 marker 或补权限代替授权。启动不新增会话、分派或批准。

打开 `http://127.0.0.1:8765/local-entry` 的“来源事实输入与历史一致性检查”，或 `/local-facts`。本次复用已有合成会话，不创建新身份或凭据。

1. 输入已有本机合成会话。选择地区、员工人数或服务诉求，填写取值、来源编号/版本、摘录和明确有效期；本机时间在提交时转换为 UTC。只有合成来源可提交，员工人数必须是非负整数，0 不算缺项。
2. 确认未经核实的合成来源，明确保存。记录原来源编号和请求编号；确认已保存后，明确结束原提交核对，再录入另一来源。旧来源保留，新来源不会覆盖旧矛盾。
3. 填写此次核对目的并明确提交三个字段的一致性检查。原 worker 检查**执行时当前身份下**已保存的来源，不调用真实模型，不自动创建 Case 或推进计划。
4. 用原运行编号“只读查看原检查”。原目的、时间、来源版本/摘录/取值/单位/有效期、冲突或缺项、下一步条件来自已保存回执。以后新增来源不改写旧回执。
5. 正常停止并重启原 launcher 后，可以在新浏览器输入原会话和原运行编号，只读恢复。`/tmp` 会被系统清理，并非生产备份。

这些是 owner 级三个字段的合成来源记录，不是新建或绑定某个 Case 的事实选择。不同目的检查共用本人已有字段来源，历史结果仅反映原评估时点，不能当作今天仍有效或已获核准的事实。

## 拒绝及响应未知

READ 与 WRITE 独立：撤销字段 READ 后不能读该来源、读包含该字段的回执或提交该检查；这不会凭空撤销仍有效的 WRITE。撤销 WRITE 后不能新增该字段来源，但现有 READ/EXECUTE 仍可能允许只读或检查。撤销 EXECUTE 拒绝新增来源和检查，撤销身份拒绝全部受保护操作。重启不 seed、不补权；拒绝响应保留原审计行为。

两个写请求都只调用原 API。页面在发送前保留原 key、类型、字段、身份散列和原参数散列，**不把 token 或事实正文写入浏览器存储**。响应未知时禁止新提交，只能 GET 原请求。新增 `/api/local-facts/requests/{key}` 是当前 owner/park/org/字段 READ 下的只读元数据读取，返回原 ID 与原参数指纹，不新增业务写能力。

同页重载先恢复句柄，空身份、另一身份或无效句柄不能覆盖它。只在原 key 的服务器指纹与原参数匹配后，才允许明确结束核对；`NOT_FOUND` 不证明未执行，不自动重试。新浏览器可手输原 key、类型和原字段 GET，或直接用原 run ID 读取。切身份及 A→B→A、读取选择 ABA 后的迟到响应不会覆盖当前视图；拒绝时清空已读取内容。
