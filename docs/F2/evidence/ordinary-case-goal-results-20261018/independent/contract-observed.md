# 普通 CaseStep 到原计划核验与事项核对包

基线：`5e657633ea9b132f994a7a5ed4e35e9556100a2d`；仅正常开发分支。

原文依据：`docs/sources/V1/平台产品设计 (2).md` §5.5 要求区分通知、阅读与履约，并核验实际材料、责任接受和回执；§5.4 要求每步有交付物和验收要求。`docs/sources/V1/分阶段开发计划 (2).md` F2 T02/T04/T07 要求覆盖、角色回执、完整记录及持久化后的正确刷新。当前普通 CaseStep 已有持久接单和人工回执，原计划 P3/P4 来源仍只认可 Run assignment；原事项核对包依赖该来源，形成业务断点。

本片只让显式 `CURRENT_PREPARATION` 普通服务向原计划提供当前 P3/P4 来源。复用原 ADOPT、P1/P2 前置、依赖失效、原事件证明、owner VERIFY、goal-results、事项核对包及两次新鲜 GET。无自动核验，无新包格式，无新工作流算法。普通模式的执行者不因此获得计划、全 Case 或 Run 读取权。

入口依赖必须由工厂/显式 create_app 的精确普通服务注入到同一 Store。marker 仅作为验证材料，不能选择权限路径。默认、旧隔离服务及未配置入口继续原拒绝行为。已有任意 Run assignment（含 inactive）、Native 字段或混合 provider 均拒绝；不先尝试旧权限再回退。

事务内复用原普通服务的 parent、首次 OFFER marker/fingerprint、ACCEPT→CREATE、人工回执历史和当前授权 generation 验证。首次 UUID 与不超过 300 秒的绝对期限不延长。普通来源指纹纳入原 P3/P4 source，旧核验不能沿用到新来源。最终事务回调在所有锁等待后重查当前性，过期不能提交 VERIFY 或返回假当前结果。已过期或撤权的合法历史保留，但 P3/P4 不再当前；结构损坏、外域、旧 marker 准确拒绝。

P1/P2 的材料/目录/资源规则、声明约束、人工决定、版本和依赖保持原算法。本片不接通生命周期 P5；其原核验和写入门槛不放宽。所有目标、未知/不支持目标和 PARTIAL 保留；不声称 Case、实际履约或机构受理完成。

验证使用独立拥有的合成 PostgreSQL 资料和既有测试角色配置，与真实初始化严格分开。覆盖普通 HTTP 流程、重建服务/进程后的读取、原 HTML 核对包、缺前置、expiry/ABA、撤权、外域、marker 损坏、默认入口拒绝及最后锁等待。独审仅写私有运行目录。不得新增真实身份、Grant、分派、目录、批准或凭据；不得部署、改 main、强推或调用真实模型。

正式 Windows/浏览器/AT35 真实场景仍未验证。交付报告必须列出真实普通运行所需的现有身份/授权/目录/来源及尚缺的管理初始化代码，不能笼统称为只缺用户权限。
