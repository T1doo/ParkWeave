# 固定验收源码校验的有界分批

基线 `e08f2f60f87ff54bdbb3a2e9f9bdd9b60dc46e03`。本片唯一代码改动是修复原固定验收入口对合法当前源码集合的容量拒绝，不新增业务功能、loader、来源适配、验收定义或统一框架。原 AT21/32 的拒绝与旧风险窗口保留，不重试它们。

原 `verify_head_test_sources` 在 HEAD/路径/hash/header 检查之后、业务测试之前，对全部 test blob 的合计4MiB作拒绝。当前381个blob共4,768,614字节，最大55,659字节，各原件等于工作区；选择单项 AT 仍核全部源码，不能靠缩减校验集合逃过该门。

沿原接口按排序路径分批读取，每批 blob 内容合计最多4,194,304字节，最大单文件仍为该值，路径总数仍最多1024。所有 HEAD/blob/manifest SHA256/工作区原始字节三方对照、LF/CRLF、symlink/路径、header/大小/分隔符/尾字节及固定错误分类保持。每个原 Git 调用仍5秒；累计内容与调用次数比旧全体4MiB上限增加，不能声称全函数资源预算完全不变。分批失败仍整体拒绝，不返回部分校验成功，不开始pytest。

只在自有临时 Git fixture验证批次边界、跨批篡改与原拒绝门；在最终冻结 HEAD 对全部当前test源码作只读校验。必要时原 runner仅选择新的AT13工程入口，使用新拥有SYNTHETIC PG和实际worker，不执行旧AT21/32、平台风险或HTTP UNKNOWN窗口，不刷全量。

固定42项定义与 whole_status 不改，pytest成功最多为工程 PARTIAL_PASS，不能回填正式PASS。Windows、LIVE、C0和业务功能缺口分别列入本轮固定清单审计；不改main、不强推、不部署、无真实模型/凭据/业务权限或安全网络权限变化。独审只静态，动态成绩单列。
