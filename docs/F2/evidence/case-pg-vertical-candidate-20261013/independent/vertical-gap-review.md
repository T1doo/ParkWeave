# Vertical acceptance gap review

Feasible, with an explicitly reviewed replacement for the session `pg` supplier. The original seven PostgreSQL test bodies and original per-test fixture can remain unchanged. The current Linux `pg` fixture always invokes pgserver, whose local implementation includes process scanning/termination, shared runtime locks and atexit deletion. It is not the already-reviewed owned-Popen cleanup contract; merely running it nonroot is insufficient to claim equivalent containment. Root-only identity/permission branches are not exercised in nonroot mode, but the candidate should not depend on them.

The replacement needs only get_uri() plus the original capture_fixture_cluster proof attribute. Create restricted parkweave_app once in the fresh cluster and pass an owner DSN with private Unix socket, new empty passfile and disabled SSL/GSS. Keep each original UUID database creation, original receipt, migrate, synthetic seed/grants, in-process TestClient and bounded ordinary DROP teardown. Prove the override is selected instead of pgserver. Keep the catalog control database separate: one original test requires absent added storage and exactly nine proposed changes; owner-as-writer REFUSED and dangerous-system-role REFUSED are expected successes of those regressions. Never grant pg_execute_server_program.

The JSON lists a proposed **14-case minimal existing-test selection: original seven + seven vertical cases**. The vertical cases exercise persisted local Run/Case creation and preparation, close/reopen, cold receipt recovery, two pre-first-acceptance cancellation lineages, cross-tenant denial and transaction rollback. They use actual database calls through the original API/TestClient and Store; they do not need a listening HTTP server, new OS identity or model/network operation. Exact function names and selected parameter values were inspected, without collecting or running tests. Any unselected parameter family remains NOT_RUN.

Keep the earlier catalog app-deny/writer-allow control in its own fresh database/scope; function ACL changes in one database do not establish ACL state in later fixture databases. The previous catalog-only authorization is spent: the new candidate requires its distinct 25-minute one-run gate and reviewed source/approval binding. Pytest logs can include SQL, DSNs and generated bearer tokens on failure, so redirect all Python/native output to private files and publish only fixed IDs/states. A teardown failure cannot be counted as a passing case.

Qualifications: a Python test harness may use threads, and real PostgreSQL itself uses multiple processes. Business identities are synthetic tokens sharing the fixture SQL app role; they are not separate OS users. New privileged-owner setup and broad fixture grants are not least-privilege production proof. Reconstructing Store proves persisted cold object reads, not process restart/crash recovery. Local closure/acknowledgment is not external acceptance or real fulfillment. No host/IPC/OS isolation, browser, service lifecycle, deployment or paid/model calls are covered. Do not run all imported test modules: some unrelated preview tests open sockets and launch uvicorn.

An optional accepted-but-never-submitted cancellation case exists, but it is a different scope from cancellation before first acceptance; add it only as an explicit selected case. This review made no PostgreSQL/CI/network/test calls and changed no tracked file. Source paths, hashes and exact proposed nodes are in vertical-gap-review.json.
