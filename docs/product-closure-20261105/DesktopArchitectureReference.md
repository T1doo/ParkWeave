# 借鉴 Sim2Act 的桌面集成方式

依据：用户提供说明，并于本轮只读查看 E:/Github/Sim2Act 的 Sim2ActDesktop.cs、desktop_protocol.py、desktop_service.py。没有运行或修改该项目，没有读取数据库配置、密码或密钥。

园合采用的目标结构保持：独立EXE → 自有后台监督/私有管道 → 实际就绪核验 → WebView2加载原本机API所提供的前端。业务API和生命周期管道分离；不重写前端、不用网页预览代替Windows交付。

可直接借鉴：

- 前端和API沿用原有代码；桌面宿主仅负责窗口、导航、文件交互与生命周期。
- READY包含本次启动绑定而不是固定等待或只看端口；园合继续采用自身原Controller/workspace.check及原身份。
- STOP处理区分未创建后台与后台已创建，并设置有限等待；不把PID退出单独当成干净停止。
- 共享身份记录由写入方保持句柄时，读取方使用兼容的共享方式，但继续核对记录/会话/进程绑定。这个规则不能扩展成对不可变程序文件允许任意写共享。
- 包、程序数据、用户凭据分离；不从其他项目复制运行环境配置或授权。

园合当前补充：初始化前也要显示同一套前端引导。此阶段的页面由EXE内存提供，禁止网络业务请求；真正的办理页面仍须等原后台就绪再加载其本机地址。内部 .invalid 地址只作进程内路由，无外部站点、无外部浏览器。

当前缺口仍包括启动消息到原处理器的转发、引导profile与正式profile交接、原生初始化/重开验收。不会把内存引导页显示成功当成完整软件可用。C++宿主已经存在，本轮借鉴生命周期方法，不为更换宿主语言而重新重写一遍。
