## 04｜资源页：消除重复，不压缩事实

![图 2｜资源页。日期链接的蓝色轮廓是截图中的焦点状态，不是误绘边框。](assets/after-resource.png)

**V：** 数量与预检已靠近、日期对齐；但选择框、其下全文和摘要重复资源名，目录读取说明仍占较高空间；“短期占位”约从 y=854 才出现。[P1][P3]

**U4｜P1｜目录与资源选择区。** 保留一处默认可完整阅读的真实名称和一处摘要引用；不要同时展示两段相同全文。读取成功改为紧凑回执，错误/权限拒绝保留完整原因。名称不能用字符串裁剪删掉“合成”“非预约证明”等原始边界。目录说明与名称字段若本来混合，先保留原文，另提受控 DTO 改造。

## 07｜缩放与低高度：新的高优先级缺口

![图 5｜原包 720×450 等效视口，按原比例展示。它不是 Windows 原生缩放实测。](assets/detail-200-percent-equivalent.png)

**U13｜P1｜720×450 等效视口。** 品牌、导航、合成身份区域占去上方约 254px；再叠工具栏和返回入口，事项标题接近视口底部才出现。无横向溢出不代表任务易用。这里只是等效视口证据，不能据此声称原生系统缩放已验或直接判定 WCAG 不合格。[P1][P2]

修改：窄宽或低高度时用紧凑应用头；导航保持可到达，合成会话输入/说明进入可展开区域；当前身份与环境用短标签保留。未决请求或权限警告不能跟工程说明一起折叠。提供“跳到当前事项”入口；打开详情后焦点进入标题/当前动作，不停在折叠壳层。

验收：720×450、1024×640、320 CSS px、真实浏览器 200% 缩放与系统字号放大分别记录。缩放后可完成搜索、读取、材料操作和恢复；无固定条遮挡最后一项，无触发器离屏后焦点丢失。以任务可达为准，不锁死标题 y 坐标。[W5][W8]

**不要采用：** 缩小正文字号、隐藏关键警告、把全部导航永久移除、强制横向滚动，或取消会话保护来“腾空间”。

## 按钮等级与对比度
主按钮：清晰蓝底与文字、高光只做轻微表面反馈。次按钮：近实色/轻磨砂、深文字和可识别边线。文字动作：不加完整卡片阴影。危险操作写具体对象；菜单项不能只剩图标。

普通文本按至少 4.5:1，必要非文字控件/状态辨识按 3:1 检查；真正的 inactive 控件有标准例外，但仍应让禁用原因可读。对玻璃面按实际背景合成最不利情况检查，而非只算对白底。[W6][W7]

## 10｜组件状态、动态交互与实现边界

**U15｜P1｜组件状态板。** 至少包含 Button、Field、ScopeNotice、ReadState、MaterialRow、RecordRow、ResourceSummary、PlanStep、Menu/Popover、RecoveryPanel。名称是职责建议，不要求新增同名框架文件。

每个组件覆盖默认、hover、active、focus-visible、selected、disabled、busy，以及业务相关的 stale/UNKNOWN/error。busy 仅表示原请求进行；selected 仅表示选中；verified 必须附范围。不得用一套“成功绿”覆盖这些差异。

## 动效规范 [N；参考 W2]
| 动作 | 目标与约束 |
| --- | --- |
| 按钮 hover / press | 120–160ms 色/光变化，按下 80–100ms、约 1px 位移；不改变布局尺寸，不模糊文字 |
| 列表与分类 | 局部底色/选中轨 120–180ms；不让所有记录同时滑入；切分类不自动读取 |
| 菜单和阅读层 | 140–180ms、最多约 8px 位移；Esc/外点/选择之后按原规则回焦；退出不拖延敏感数据清理 |
| 页面切换 | 短淡入可选；不做整页飞入或视差，保留用户位置 |
| 鼠标高光 | P2 可选，只对当前控件、精细指针启用；低强度、单帧合并；不用全屏追光/粒子；默认不妨碍正文 |

减少动态、低效果、后台和强制颜色分别设计。保留可关闭的触感增强，不能把装饰完成动画当作请求成功。一次 rAF 采样不是 FPS 或设备性能认证；需在真实目标浏览器记录多次滚动/输入 trace。[P3]

## 前端工程约束
先审本地 workspace_design.css/js 与 web.html 差异。统一 token 和职责层，不在文件末尾继续叠覆盖；保留现有 ID、form owner、原生校验、授权及恢复处理器。对现有 MutationObserver 先量测触发与重复渲染，再最小范围优化，不凭猜测全量重写。

展示逻辑可以映射服务器状态，不应从中文文案推断授权或业务终态。保留当前原处理器作为唯一写入入口；必要只读适配也要复用当前身份和来源校验。浮层、sticky 和模糊容器的层叠、裁切与焦点在真实渲染中验收。

## 12｜BE1/BE2：先闭合本地真实办理与可靠性

## BE1｜P0｜同一冻结版本的四角色真实浏览器链
**输入：** 独立新测试根、明确批准的隔离 PostgreSQL、原 API/worker、四个不同角色；全部业务资料显式合成。安装/配置前置允许通过受审安装器完成，业务中途不得手改库“补完”授权或状态。

**执行：** 企业提出新目标并补材料 → 专员补正/审核 → 企业确认及明确采用 NO_MODEL 方案 → 资源预检/占位/组合及关联 → 专员分派 → 执行者本人接单并提交回执 → 企业核对 → 合法本地关闭/重开 → 停止并以同目录重开回读；再用不同输入创建第二事项。

**证明：** 每一步均记录浏览器动作、真实 HTTP、数据库事件与原 key/版本；技术 Run 成功不替代 Case 目标结果。再次运行不复制旧材料/授权/回执。旧“首次体验”与新完整样例的 assignment 前置分别验证，不能据旧说明判所有入口都必须手改库。[R2][R7][R11]

**通过界限：** 先形成“本地合成四角色链通过”结论；它不是自动通过 LIVE、Windows 或完整正式 AT-35。发现真正缺少的业务入口，再按最小契约补实现，不只修演示脚本。

## BE2｜P0｜资源、撤权与 UNKNOWN 故障验收
| 不变量 | 必须运行的反例 |
| --- | --- |
| 组合原子性 | 两资源同时确认，其中一项冲突；不得出现未说明的部分成功或重复占用 |
| 容量与幂等 | 并发争最后名额；同 key 同请求重试只产生一次效果，同 key 不同指纹拒绝 |

## 13｜BE3/BE4：模型和正式来源不是填一个密钥

## BE3｜P0 产品门｜真实模型链分两层完成
**已有事实：** LIVE worker 文档只明确 case.create；service_selection_planner.py 是 OfflineSelectionPlanner，显式依赖离线传输，返回 provider_enabled=False。不能把这两条链混成“智能服务编排已上线”。[R4][R5]

**第二层：** 对受控服务选择/计划路径增加获批准的 LIVE 接口适配。继续只让模型提出可信目录引用/有限计划；服务端重建依赖、核验目标覆盖、角色、来源版本与资源约束。最小上下文，不转发无关材料或身份秘密。

**必须验：** 缺批准前零调用；截断/非法 JSON/未知服务拒绝；429 和超时不无界重试；已发送未知不退款、不重发；撤权时分清派发前和在途。无账户授权只阻塞 LIVE 门，不阻塞本地功能。

## BE4｜P1｜受审 ServiceSpec 与来源接入
原设计要求资格/材料/资源/动作/责任/有效期/来源引用形成可执行规格。当前合成发布契约是受限子集；应先用一组有授权或可合法使用的有限服务说明验证，而非立即建设无限目录平台。[D1 §5–6][R6]

实施工作：建立或完善来源登记→候选提取→人工审核→不可变发布→配置映射→当前适用性校验的实际入口。缺正式规则/人工判定保持 UNKNOWN；不得仅把 SYNTHETIC 改成 REAL，或将 business_publication 直接翻成 True。

当前资源管理员样例仍只读。若完整产品要支持资源/目录维护，必须先明确服务端管理角色与授权、审计及发布契约，再增加对应页面；不能给现有样例角色自动补权。可先保留受限产品范围，并在规范中说明未启用能力。

**验收：** 未审核不能用于承诺；来源撤回/过期使新操作重新核验，旧历史保留；缺事实不编造资格；材料齐全与官方批准仍分开。PR0 不要求接入真实外部写系统。[D2 AT-21–23、28]

## 14｜BE5/BE6：变化、模板与可复制性

## BE5｜P1｜变化闭环与模板不能只验“拒绝成功”
已有 AT-25/26/27 工程绑定涉及两事项影响集合、人工锁、历史保留及不兼容发布拒绝；AT-27 明确未证明实际回退执行。应针对产品承诺补完整路径，而不是把所有保护性拒绝都解释成升级/回退功能完成。[R3]

## 16｜测试计划：从“页面不报错”到“任务成立”

**Q1｜P0：** 同一测试报告分别保存实现状态、执行状态、验证范围；PASS 不替代环境，SKIPPED 不计通过。当前 7 passed / 6 skipped 是本轮特定 Python 集合，不是整个后端通过率。[P1]

| 测试层 | 必须证明 | 不能替代 |
| --- | --- | --- |
| 纯逻辑/契约 | 状态映射、日期、三值、输入拒绝、权限和来源绑定 | 浏览器、真实账户、原生运行 |
| DOM/回调 | 原 ID/handler/form 关系、清理、焦点回调、菜单路径 | 字体像素、原生键盘传播、读屏 |
| 浏览器＋mock | 布局/焦点/范围/副作用次数，三种恢复状态 | 真实数据库并发、实际占位/履约 |
| 实际 API＋隔离 PG＋worker | 事务、幂等、过期、租约、回执持久化 | 最新页面与四角色全过程 |
| 浏览器＋实际后端 | 新事项、补正、采用、占位、分派、核对、重开 | LIVE 模型或 Windows 宿主 |
| LIVE/原生/独立评价 | 分别运行并提供对应目标证据 | 不能彼此代签 |

## 前端覆盖矩阵
四主页面 × 当前真实角色可见范围 × 正常/空/错误/拒绝/陈旧/提交中/UNKNOWN。按风险选择组合，不要求无意义地排列所有组合。重点加入服务目录成功与多方案、资源最后名额/到期、派单拒绝、回执重开、权限撤回和材料版本变化。

尺寸包括 1280×800、1440×900、1920×1080、1024×640、720×450 与 320 CSS px；真实浏览器缩放/Windows 系统缩放/文字放大分开记录。低效果、无 blur、减少动态、强制颜色测试不只检查 overflow，还要完成主要任务。[W5]

## 可访问性与性能
键盘顺序、菜单 Esc/回焦、日期网格、状态播报、隐藏副本、输入法、文本选择、剪贴板失败和真实读屏。焦点不能被作者创建的固定区域完全遮住；产品尽量做到全部可见。[W8]

对比度检查覆盖实际背景、hover/focus/disabled 语义；自动扫描只是补充。性能在同一设备/浏览器、固定样例下记录多次输入与滚动 trace、长任务、重复渲染和内存趋势；不把 119 次 rAF 采样写成“稳定 240 FPS”。[P3][W6][W7]

## 四条发布结论必须分开
**前端候选通过：** 布局/状态/交互达标，不等于业务验收。
**本地合成办理通过：** 实际数据库、角色和恢复可用，不等于真实园区或 LIVE。
**PR0 验收通过：** 按原规范或经明确批准的新版规范逐项有证据；不通过“改个版本名”取得。
**真实园区/生产可用：** 还需授权数据、来源、运维和实际应用证据，不由漂亮截图推导。
