# Windows 独立应用交付计划

生效：2026-11-05，依据用户最新明确决定。此计划优先于旧执行计划的 Linux 路线与交付顺序；不修改历史证据，不宣称现有软件已可用。

## 产品是什么

园合 ParkWeave 当前要交付 Windows 桌面软件。用户从 ParkWeave.exe 启动，在独立应用窗口中登录、办理、关闭和重新打开。正常使用不要求用户打开浏览器、复制 localhost 地址、运行终端命令、安装 Python 或管理 PostgreSQL。

现有 HTML/CSS/JavaScript 界面可继续复用，由 Windows WebView2 嵌入独立窗口；使用网页渲染技术不等于要求用户用浏览器。API、worker 和数据库在应用后台由宿主负责启动、检查和关闭。功能与持久化不能只靠外壳窗口。

Linux 开发、部署、安装与验收暂不推进，也不是本轮 Windows 交付的前置条件。历史 Linux 测试仅保留原环境标签。

## 保留的工作

**用户进一步明确：直接使用前面已经设计好的新前端。** 正式工作台继续使用现有 web.html、workspace_design.css/js，不另做一套 Win32 视觉界面。首次启动和打开已有工作台也应复用这些前端样式/组件，在同一个 WebView2 窗口内完成；原生宿主只承担窗口、受限桥接、目录选择和后台生命周期。不能把初始化工程表单作为软件首页，也不能只修改工程表单的颜色字体当作完成。

当前阻点是初始化前尚未创建工作台 WebView/profile，现有 showWeb 仅在后台 RUNNING 后调用。后续需实现初始化阶段的受限前端承载与桥接：真实安装状态、原输入校验、原新建/重开处理器不变；禁止外部导航、远程资源和任意命令；不能通过取消后台门来展示假 RUNNING。用户输入密码不得写日志或配置明文。

- 保留当前分支全部 UI、状态、键盘、资源、协同及材料改动，继续采用蓝白淡紫、受控磨砂、实色正文。
- 保留原 API、角色隔离、幂等、UNKNOWN 核对、来源与版本检查；不因桌面包装取消限制。
- 保留实际存在的 EXE → desktop_bridge → entry/controller → WebView2 原生路径；先核源码当前实现与门，再修缺失实现。

## 当前事实与缺口

仓库已有 Windows EXE/WebView2 宿主和私有运行时启动链，不能称从零没有桌面实现。但当前 release 文档记录 new 在 OWNER、reopen 在 fixed journal/loader 等门仍未闭合。必须核对当前函数是否有后续变化，以当前代码与 Windows 实跑为准。

这些是 Windows 自身的初始化、身份保护、持久恢复和依赖加载问题，不是“先装 Linux 就能解决”的问题。不能把仅显示初始窗口的旧包称为可用软件，也不提供只在浏览器能运行的前端作为最终成品。

## 实施顺序

1. **W0 当前资产盘点**：核 EXE 宿主、私有 Python/PG、WebView2、依赖锁定、构建脚本、现有本地包及实际准入函数；冻结源码/包哈希，不混用旧包。
2. **W1 Windows 运行闭环**：补齐当前初始化和同目录重开所需实现；默认普通用户；使用明确的新建应用测试目录；不覆盖旧资料、不创建系统账户、不关闭系统防护。确需额外权限的具体动作另行说明。
3. **W2 独立窗口体验**：应用图标、标题、窗口缩放、键盘、日期、滚动、加载/故障页、关闭行为；主入口不启动外部浏览器。开发浏览器测试只是辅助。
4. **W3 本地真实业务链**：通过应用正常安装/初始化入口建立合成测试配置，在独立窗口完成新事项、材料补正、核对、方案、资源、派单、回执、重开及第二次新输入；每步原 API 落库，中途不手改库补状态。
5. **W4 生命周期与数据保护**：窗口关闭后本实例后台有界退出，保留数据；再次启动回读同一事件；中断/未知结果显示安全恢复入口，不自动重复提交。普通退出与断电验证分开。
6. **W5 可用包**：产出同一冻结版本的完整便携 ZIP 或安装包，包含实际运行依赖及最新界面；明确 Windows/WebView2 前提与首次启动体验；在干净测试位置实际启动、办理、关闭、重开，再登记可用结论。

## 验收门

- EXE 可启动 ≠ 业务可用；打包成功 ≠ W3/W4 通过。
- 软件主流程无需用户操作浏览器、终端或数据库。
- 四角色能力只按服务端实际配置开放，资源管理员现有只读范围不自动扩权。
- NO_MODEL 本地合成路径可以作为明确标注的可用范围；LIVE 与正式园区来源分别验，不假冒已接通。
- 所有 Windows 门用 Windows 证据核对，不能拿 Linux 或 mock 代签。
- 缺陷应修实现；测试用于证明，不能长期只补截图而不推进可用包。
